# Circle Note / コミケの訪問手帳

開催回ごとに訪問したいサークルを整理する、個人用Webアプリです。React + TypeScript + Vite。サーバー・アカウント・有料サービスは不要です。

## 起動

Node.js 22以上推奨（検証: 24.19.0）、npmを使用します。

```sh
cd /workspace/comiket-map
npm ci --cache /tmp/circle-note-npm
npm run dev -- --port 5173
```

通常のPCではターミナルに表示されたアドレスをブラウザーで開いてください。同一LANのスマートフォンから閲覧する場合はPCのLANアドレスを使います。開発サーバーをインターネットに公開しないでください。外部公開は行っていません。

```sh
npm test
npm run build
```

ビルド結果は `dist/` に生成されます。

## 操作

1. 開催回を追加し、日目とホールの候補を入力します。候補の入力順が一覧の整列順です。
2. サークルを登録します。必須は名前、日目、ホール、場所、優先度（1〜5）。URLまたはXの@ユーザー名は任意です。
3. 一覧から編集・削除できます。検索、日目・ホールの絞り込みにも対応します。
4. 変更はその都度このブラウザーのlocalStorageに保存します。再起動後も同一オリジン・同一ブラウザープロファイルで復元します。
5. 「JSONを書き出す」で全開催回をバックアップできます。「JSONを読み戻す」は検証・確認後に全開催回を置き換えます（マージではありません）。

保存は端末・ブラウザーごとです。自動同期はありません。PCとスマートフォン間ではJSONで移行してください。ブラウザーのデータ消去やプライベートモードでは失われる場合があります。サークル名等の情報は外部送信しません（リンクを開く場合はリンク先へアクセスします）。保存容量不足などの失敗は画面上に表示し、成功扱いにしません。既存データが読めない場合は上書きを止め、バックアップの読み戻しを案内します。

開催回の候補は作成時に設定します。現段階では開催回名・候補の後編集用画面はありません。サークルの編集・削除には対応しています。

## 技術とデータ設計

- React + TypeScript: 入力と一覧更新を型付きで管理。Vite: 軽量な開発環境と静的ビルド。
- Next.js + DB は将来の端末同期には適しますが、今回はサーバー管理なしで個人利用できる構成を優先しました。素のJavaScriptより、後続の座標・ルート追加で型検証を効かせられます。
- `src/data.ts`: UIから独立した型、整列、編集、JSON検証。保存形式は `version: 1`。
- 開催回は安定したID、名前、順序付き日目・ホール候補、サークル、マップ、日目別ルートを持ちます。
- 並び順は日目の設定順 → ホールの設定順 → 優先度降順 → 名前の日本語比較 → ID。日目とホールは値の降順ではなく設定順、優先度は5が最上位と解釈しています。
- `locationRaw` は前後空白を含め入力原文を保持します。名前とリンクの前後空白は除去します。
- `placement: null` は未配置。確認済み位置はマップID、0〜1の正規化座標（左上原点）、確認状態、手動/PDFの情報源を保持します。日目・ホール・場所を変更すると古い座標を無効化します。
- マップには画像等の参照、ホール、座標系、公式/サンプルの区分があります。`routes` は日目からサークルIDの配列への対応で、順序を保持します。日目変更・削除時はルートの参照も整理します。
- JSON読み戻しでは必須項目、候補、ID重複、リンク形式、座標範囲、マップ参照、ルート参照を検証します。未知のバージョンは拒否します。

## 検証

`npm test` は9件。混在データの整列、同名時の安定順、編集とルート参照整理、JSON往復と原文保持、不正値拒否、確認済み座標保持と解除、リンク検証、およびDOM環境で開催回作成→登録→編集→再マウント復元→JSON読み戻し→削除を確認します。書き出し操作でBlobが生成されることも検証しています。

`npm run build` と開発サーバーへのHTTPリクエストも検証済みです。実ブラウザーの自動テストはブラウザー取得先へのネットワーク制限で未実施。実際のファイルダウンロード、スマートフォン実機、複数タブ同時編集は未確認です。同時編集時の競合解決は未実装です。

## 次の段階

今回のUIは登録・整理・保存まで。マップ・訪問順編集・自動位置認識は未実装です。仮の会場や座標は初期データに含めていません。テスト内の架空データは検証専用です。

必要な資料:

- 対象の開催回名、参加日目、公式ホール区分
- 利用可能な公式会場PDF（開催回・日目・ホール・ページの対応）
- 位置を検証できる数件の配置番号と、PDF上の正しい位置
- PDF/画像の利用条件

PDF認識は別モジュールで候補座標と根拠を生成し、人が確認した位置をこのデータ形式へ取り込みます。文字の読み取りだけでは位置認識成功と扱いません。マップ表示側はPDF認識に依存せず、確認済み座標を使える構造です。画像の参照先・永続化方法やPDFページと画像座標の変換は、実資料を使って次段階で確定します。同じホール内の線・矢印と手動訪問順を後続で追加し、自動ルート最適化は対象に含めません。
