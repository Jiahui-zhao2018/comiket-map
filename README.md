# Circle Note / コミケの訪問手帳

開催回ごとに訪問したいサークルを整理する、個人用Webアプリです。React + TypeScript + Vite。バックエンド・アカウント・有料サービスは不要です（ローカルの開発サーバーは起動します）。

- [要件と実装状況](docs/requirements.md)：要求・現状・将来構想・既知の差。
- [プロジェクト指示](AGENTS.md)：今後の作業の継続条件と検証方針。
- [開発レポート作成スキル](.agents/skills/development-report/SKILL.md)：レポート依頼の再利用手順。対応エージェントでは `$development-report` を指定するか、このファイルに沿ってレポート作成を依頼してください。

## 起動

Node.js 22以上推奨（検証: 24.19.0）、npmを使用します。

リポジトリをPCに取得し、そのディレクトリで実行します。

```sh
cd comiket-map
npm ci
npm run dev
```

アクセスURL: **http://127.0.0.1:5173/**

開発サーバーは `127.0.0.1:5173` のみで待ち受けます。停止は起動したターミナルで **Ctrl+C** を押してください。ポート使用中の場合は別ポートへ移動せずエラーで停止します。使用中のプロセスを確認してから再起動してください。`--host` で待受設定を変更しないでください。

バックエンドはありません。LAN経由のスマートフォン閲覧は現段階ではできません。外部ホスティングやトンネルは使用しません。ビルド確認用の `npm run preview` も `127.0.0.1:4173` 限定です（先に `npm run build`、停止はCtrl+C）。

localhost名・IP・ポートが変わるとブラウザーの保存先も変わります。以前別のURLで保存していたデータは、そのURLでJSONを書き出してから新しいURLで読み戻してください。

```sh
npm test
npm run build
```

ビルド結果は `dist/` に生成されます。

## 操作

1. 開催回を追加し、日目とホールの候補を入力します。候補の入力順が一覧の整列順です。
2. サークルを登録します。必須は名前、日目、ホール、場所、優先度（1〜5）。URLまたはXの@ユーザー名は任意です。
3. 一覧から編集・削除できます。検索、日目・ホールの絞り込みにも対応します。
4. 変更はその都度このブラウザーのlocalStorageに保存します。再起動後も同一オリジン・同一ブラウザープロファイルで復元します。
5. 「JSONを書き出す」で全開催回をバックアップできます。「JSONを読み戻す」は検証・確認後に全開催回を置き換えます（マージではありません）。

保存は端末・ブラウザーごとです。自動同期はありません。別のPCやブラウザーへはJSONで移行してください。ブラウザーのデータ消去やプライベートモードでは失われる場合があります。サークル名等の情報は外部送信しません（リンクを開く場合はリンク先へアクセスします）。保存容量不足などの失敗は画面上に表示し、成功扱いにしません。既存データが読めない場合は上書きを止め、バックアップの読み戻しを案内します。

開催回の候補は作成時に設定します。現段階では開催回名・候補の後編集用画面はありません。サークルの編集・削除には対応しています。

## 技術とデータ設計

- React + TypeScript: 入力と一覧更新を型付きで管理。Vite: 軽量な開発環境と静的ビルド。
- Next.js + DB は将来の端末同期には適しますが、今回はサーバー管理なしで個人利用できる構成を優先しました。素のJavaScriptより、後続の座標・ルート追加で型検証を効かせられます。
- `src/data.ts`: UIから独立した型、整列、編集、JSON検証。保存形式は `version: 1`。
- 開催回は安定したID、名前、順序付き日目・ホール候補、サークル、マップ、日目別ルートを持ちます。
- 並び順は日目の設定順 → ホールの設定順 → 優先度降順 → 名前の日本語比較 → ID。日目とホールは値の降順ではなく設定順、優先度は5が最上位と解釈しています。
- `locationRaw` は前後空白を含め入力原文を保持します。名前とリンクの前後空白は除去します。
- `placement: null` は未配置。確認済み位置はマップID、0〜1の正規化座標（左上原点）、確認状態、手動/PDFの情報源を保持します。日目・ホール・場所を変更すると古い座標を無効化します。
- マップには画像等の参照、ホール、座標系、公式/サンプルの区分があります。`routes` は日目からサークルIDの配列への対応で、順序を保持します。日目変更・削除時はルートの参照も整理します。
- JSON読み戻しでは必須項目、候補、ID重複、リンク形式、座標範囲、マップ参照、ルート参照を検証します。未知のバージョンは拒否します。

## 次の段階

現在のUIは登録・整理・保存、表示名入力補助、星の優先度、マップ表示と自動／手動配置に対応します。PDF位置認識・訪問順編集は未実装です。初期データは空で、架空サンプルは利用者が選んだ場合のみ専用開催回として追加します。

必要な資料:

- 対象の開催回名、参加日目、公式ホール区分
- 利用可能な公式会場PDF（開催回・日目・ホール・ページの対応）
- 位置を検証できる数件の配置番号と、PDF上の正しい位置
- PDF/画像の利用条件

PDF認識は別モジュールで候補座標と根拠を生成し、人が確認した位置をこのデータ形式へ取り込みます。文字の読み取りだけでは位置認識成功と扱いません。マップ表示側はPDF認識に依存せず、確認済み座標を使える構造です。画像の参照先・永続化方法やPDFページと画像座標の変換は、実資料を使って次段階で確定します。同じホール内の線・矢印と手動訪問順を後続で追加し、自動ルート最適化は対象に含めません。

## Xの表示名から入力補助

サークル登録・編集フォーム上部で「Xの表示名」を貼り付け、「読み取る」→候補を確認→「候補をフォームに反映」の順に操作します。元の入力文字列も表示します。反映ボタンで認識できた項目を入力済みの値へ上書きします。確認チェックや追加ダイアログはありません。人物名はサークル名と異なる可能性があるため、反映後にフォーム上で確認・修正してください。未認識・未確定の項目は元の入力値を保持します。優先度・URL・XユーザーIDには触れません。解析も候補反映も保存操作ではなく、最後に既存の登録・変更保存を行います。表示名原文はフォームを閉じるまで確認でき、登録データには追加保存しません。

ここで示す名前・アカウント識別子・配置番号、およびコード内の例示・テストデータはすべて説明用の架空情報です。実在のアカウントや開催回の配置とは無関係です。利用者が保存したデータの置換や移行は行いません。

- 架空の対応例：`架空サークルA@1日目南a-44ab`、`架空サークルB 2日目東ユ 42ab`。
- 日目：全角・半角数字＋「日目」（途中の空白も可）。開催回の候補と数字・空白を正規化して照合します。
- 配置：東西南北のエリア（省略可）、英字またはカタカナ1文字のブロック、1〜2桁の番号、任意のa/b/ab等の接尾辞。一般的なハイフンと全角数字を整え、`ブロック-番号+接尾辞`を候補にします。
- 配置ブロックの英字大小・全半角・カナ文字種は保持します。会場固有の同一視規則は未提供のため変換しません。候補の場所文字列は利用者が修正可能で、確認した値を既存の場所フィールドへ保存します。
- ホールは「東」「東1」「東１ホール」「東ホール1」などの開催候補に照合し、該当が1件のときだけ反映します。「東1」「東2」がある場合は手動選択が必要です。新規登録の日目・ホールも未選択から始め、未確定のまま登録できないようにしました。
- 複数の日目・配置は一覧表示し、その項目は反映しません。情報が一部だけなら、確定できる部分のみ使います。確定できない項目は、反映ボタンを押しても元の入力値を保持します。
- 非対応・要手入力：漢数字や曜日のみの日目、ひらがなや複数文字のブロック、島・机など独自表現、複雑な複数配置の省略表記、具体的なホール番号を表示名から直接読み取ること。認識はヒューリスティックな候補抽出で、公式配置の存在や妥当性を保証しません。複雑な表記は必ず原文と照合してください。

Xや外部APIへのアクセスはありません。`src/displayName.ts` の純粋関数で解析し、フォーム・保存処理から分離しています。追加検証は指定2例、全角と空白・ハイフン、日目のみ、情報なし、複数配置、開催候補不一致、ホール曖昧、文字種保持、認識値の上書きと未認識値の保持に対応。DOMの画面操作でも、解析・反映時の未保存、認識値の上書き、未認識値の保持、候補修正→登録→再起動復元を検証しています。

## 星による優先度設定

登録・編集フォームで5個の星をクリック・タップすると1〜5を設定できます。3なら「★★★☆☆」となり、現在値も数値で表示します。ネイティブのラジオボタンを使用し、Tabでグループに移動、矢印キーで変更、Spaceで選択できます。フォーカス枠と読み上げ用の「優先度1」〜「優先度5（最高）」を備えています。内部データは従来どおり数値で保持し、5が最高、一覧の整列順・既存保存形式は変更しません。

既存の操作テストには、星のクリック、矢印キー操作、既存値の初期表示、変更保存と再起動復元を含みます。実ブラウザー・タッチ端末・実際のスクリーンリーダーでの動作は未確認です。localhost限定の起動設定は維持しています。

## マップで確認する

1. サイドバーの「架空サンプル開催回を追加」を押します。実際の会場ではない旨がマップ上に表示されます。既存開催回や登録内容には自動投入しません。
2. 「＋ サークルを登録」から架空サークル名、1日目、架空ホールA、場所 `A-01a` を登録してください。確認済みサンプル対応表から自動配置され、マップ上に優先度マーカーが出ます。ほかに `A-02a`、`B-01a` を試せます（すべて架空配置）。
3. マーカーまたは下の各サークルボタンで名前・日目・ホール・場所原文・優先度・登録リンクを確認できます。同じ位置に複数ある場合も、各ボタンから選べます。
4. 拡大・縮小ボタン、地図ドラッグで移動、「全体表示」でリセットできます。地図領域にフォーカスして矢印キーでも移動できます。ホイール／ピンチ操作は未対応です。
5. 未配置または配置済みのサークルを選び「位置を指定・修正」→地図クリック／タップ→「この位置を保存」。仮位置を指定しただけでは保存しません。詳細へ移動して地図が画面外になった場合はスクロールして地図を表示してください。通常の地図クリックは位置を変更しません。
6. 「配置を解除」は未配置として保存し、以後の自動照合も停止します。「自動照合を再開」で戻せます。手動位置は再照合しても上書きされません。日目・ホール・場所を編集すると古い位置を解除し、新しい情報で照合します。
7. 既存のサークルは「既存サークルを自動照合」で対応表を適用できます。対応なし・複数候補・ホール矛盾は各サークルボタンで案内します。開催回・日目・ホールを切り替えた別のサークルは混在させません。

マップがない開催回／日目／ホールでは、未設定と次の操作を表示します。画像と確認済み配置データの追加・差し替えは [マップデータ仕様](docs/map-data.md) を参照してください。画像を埋め込み保存するため再読み込みとJSON入出力で復元できます。容量に制限があるので、ファイルは3MB以下にしてください。複数画像の合計がlocalStorage容量を超える場合は保存できません。

### マップ機能の検証

今回の追加では `npm test` 36件と `npm run build` が成功。Chromiumで登録・自動配置・詳細・拡大／移動／画面幅変更後の座標・手動修正／解除・再読み込み・同座標の複数詳細・日目／開催回分離・実ファイルJSON往復・日目編集後の旧マーカー解除を検証しました。従来の登録・入力補助・星は既存DOMテストで回帰確認しています。公式の会場画像・配置、タッチ実機、スクリーンリーダー、大容量データは未検証です。

再利用できる実ブラウザーテストは `tests/map.browser.mjs`。別途PlaywrightとChromiumを用意し、localhostの開発サーバー起動中に `node tests/map.browser.mjs` を実行します。Chromium既定パスは `/usr/bin/chromium`、必要なら `BROWSER_EXECUTABLE`、Playwrightの外部配置には `PLAYWRIGHT_MODULE`（index.mjsの絶対パス）を指定できます。アプリ自体にPlaywright依存は追加していません。新しいブラウザーコンテキストと架空データだけを使用します。
