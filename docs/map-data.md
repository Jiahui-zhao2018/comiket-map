# マップ・配置データの接続仕様

対象は一開催回内の一つの日目・ホール。マップ表示と位置照合はPDF/OCRや表示名解析に依存しない。[要件](requirements.md)、[利用手順](../README.md)も参照。

## データと互換性

全体JSONは既存の `version: 1` を維持する。Eventに任意の `placementData`、各mapに任意の `day`、Circleに任意の `autoPlacementDisabled` を追加した。旧JSONのこれらの省略は引き続き読み込める。旧mapのday省略は、同じホールの背景画像を各日目で共有する意味とする（サークルは必ず選択日目で絞る）。新規設定はdayを必須とする。

`Circle.placement.source` に `mapping` を追加し、既存の `manual` / `pdf` を維持。手動・旧pdfの確認済み位置は自動処理で変更しない。解除時はplacement=nullとautoPlacementDisabled=trueを保存し、再照合でも再配置しない。「自動照合を再開」で解除できる。日目・ホール・場所の編集時は旧座標と停止フラグを解除して新情報で照合する。名前・優先度・リンクの編集では位置を維持する。

## 実資料への差し替え

1. 利用権限・出所と日目・ホールの対応を確認する。バックアップJSONを先に書き出す。
2. マップタブで対象の日目・ホールを選ぶ。画像のみを設定する場合は「マップ・確認済み配置データの設定」から区分（架空／公式資料）を選び、PNG/JPEG/WebPを追加する。公式区分は利用者が確認するメタデータで、アプリによる公式認定ではない。画像のみなら手動配置が使える。
3. 自動配置には、確認済みマップ設定JSONを作成して同じ設定欄から追加する。形式は下記。画像はBase64のData URLで埋め込む方式を推奨する。画像アップロード→全体JSON書き出しで得たmapsのassetも使える。mapIdはそのmap.idと一致させる。
4. 同じIDは追加できない。既存マップを差し替える場合はバックアップ後「このマップを削除」を使う。この削除は関連座標と対応表も除く。新資料の座標を改めて確認して設定する。複数のマップが日目・ホールに一致する場合、表示対象は利用者が明示的に選択する。

下記は形式説明用の架空例であり、`asset` の省略部分は実際のPNGのBase64に置換する必要がある。日目・ホールは開催候補と完全一致させる。

```json
{
  "map": {
    "id": "fictional-hall-a-day1",
    "day": "1日目",
    "hall": "架空ホールA",
    "asset": "data:image/png;base64,（実画像のBase64）",
    "coordinateSystem": "normalized",
    "source": "sample"
  },
  "placements": [
    {
      "day": "1日目",
      "hall": "架空ホールA",
      "location": "A-01a",
      "mapId": "fictional-hall-a-day1",
      "x": 0.25,
      "y": 0.3,
      "confirmed": true
    }
  ]
}
```

公式の確認済み資料には `source: "official"` を指定。曖昧な座標をconfirmedにして取り込まない。設定ファイルは3MB以下。任意の対応候補は、未確認のままこの配列へ入れない。画像と対応表はlocalStorageと全体JSONに保存する。一時Blob URLは保存しない。データ量がブラウザー容量を超えると保存エラーとなり、成功扱いにしない。

ローカルの相対画像パス（ASCIIのパス・png/jpg/jpeg/webp/svg）も表示可能だが、その資産を同じアプリ配下へ設置する必要があり、JSON単体では画像が移行されない。外部HTTPS画像・blob参照・SVGのData URLは表示しない。旧JSONの読み込み自体は従来の文字列参照も許容し、表示不可／画像読み込み失敗は画面で案内する。

## 照合・描画・分離点

- `src/placement.ts` の `resolvePlacement(event, circle)` が接続点。表示名解析は `src/displayName.ts` に残し、この照合では表示名を解析しない。
- 比較キーは場所文字列の前後空白を除いた値。英字大小・全半角・内部空白・カナを勝手に同一視しない。対応表は保存される場所文字列に合わせる。公式規則が必要になったら明示的な照合キーの設計として追加する。
- 同じ日目・場所の全候補を確認し、ホールが矛盾する候補があれば確定しない。一致行が一つだけでマップ・ホール・日目が整合するときのみ配置。重複行も複数候補として扱う。日目が違う行は流用しない。登録されたホールそのものは自動変更しない。
- 登録・編集で `autoPlace(updateCircle(...))` を実行。既存サークルには「既存サークルを自動照合」。設定JSON追加時も既存データを照合する。手動位置・停止状態は保持する。
- 正規化座標は画像の左上=(0,0)、右下=(1,1)。PNG内の白余白も含めた画像全体が座標面。画像と全マーカーを同じDOM面で変換し、位置指定時は変換後の実境界から逆算する。ResizeObserverと画像の縦横比で全体表示を合わせる。
- 同座標の重なりは各サークルの選択リストで詳細へアクセス可能。クラスタリングや位置をずらす描画は行わない。

## サンプルの確認範囲と対象外

`src/sampleMap.ts` がCanvasから架空ホールのPNGと3行の対応表を生成する。A-01a=(0.25,0.30)、A-02a=(0.50,0.30)、B-01a=(0.70,0.65)。図形の中心と対応するようにプログラム内で定義した架空データであり、公式会場・実在サークルの配置を検証したものではない。サンプル開催回は空のサークル一覧で追加し、既存開催回へ混ぜない。

PDF/OCR・ルート編集・最適化は未実装。PDF由来データも、この形式へ人が確認してから渡せば、認識処理に依存せず表示できる。次段階では実画像・ページと日目／ホールの対応、配置規則、正しい位置が分かる資料、利用条件が必要。
